# 4. systemd-boot Managed with sdboot-manage

* **Status:** Accepted
* **Date:** 2026-11-18

## Context

mikmakmuk uses Limine and manages `/etc/default/limine`; samos and multiberry write `/etc/kernel/cmdline`. kos boots
with systemd-boot: entries are generated by `sdboot-manage` (package `systemd-boot-manager`), which reads
`/etc/sdboot-manage.conf` and writes `loader/entries/*.conf` on the ESP. Its pacman hooks regenerate entries when a
kernel is installed or removed.

## Decision

* Never edit boot entries or `/etc/kernel/cmdline` directly.
* Extra kernel options go in a drop-in, `/etc/sdboot-manage.conf.d/99-kos.conf` (`LINUX_OPTIONS+=`), fed by the
  `kernel_options` inventory variable; the existing `/etc/sdboot-manage.conf` stays untouched. Options that the base
  `LINUX_OPTIONS` already contains are not repeated, and the drop-in is removed when nothing is missing.
* `DEFAULT_ENTRY` is `manual` in sdboot-manage, so the default kernel is set with a `default` line in
  `/boot/loader/loader.conf` (`boot_default_entry`, `linux-cachyos.conf`).
* The stock `linux` kernel stays installed as fallback; the teardown points the default back at it before removing
  `linux-cachyos`.

## Consequences

* **Positive:** survives kernel updates, uses the tool CachyOS already ships, and is easy to revert.
* **Negative:** the playbook assumes the entry name `linux-cachyos.conf`; verify with `sudo bootctl list` after the
  first run. `/boot` is only readable by root, so the playbooks cannot be dry-run checked as a normal user.
